# Ingestion and cache integrity

The monitor's own SQLite cache uses WAL and short transactions. Each source row contains normalized reducer state and a byte checkpoint in one atomic update. Browser snapshots are a projection of those normalized source states; a crash between source ingestion and projection is repaired on reconciliation without replay inflation. Provider databases remain read-only and are never migrated, repaired, vacuumed, or checkpointed.

Each source checkpoint contains namespace, absolute path, OS file identity, generation, byte offset, a fixed prefix digest, the digest immediately before the offset, file size/modification time, malformed-record count, and an oversized-record skip flag. The committed offset advances only through complete newline-terminated records. UTF-8 decoding happens after the newline is found in bytes, so split UTF-8 and partial JSON cannot corrupt the next parse. CRLF, LF, BOM, and blank lines are tolerated.

An unchanged fully consumed file needs one stat and no content reads. Reads normally consume at most 4 MiB per source. A single record may grow to a 16 MiB ceiling; larger records are diagnosed and skipped across bounded chunks until their terminating newline. The middle of an oversized record is never treated as a new JSON record. Provider records with unknown families do not stop ingestion.

Identity changes, truncation, and prefix/offset-anchor mismatches reset source state in a new generation. OS-preserving rename/archive reuses the checkpoint by identity. Identity, size, prefix, and consumed-byte anchor are checked again before commit so a replacement during a read cannot combine generations. A read lock, transient absence, reducer exception, or SQLite error leaves the previous checkpoint and state available for retry. Reducer exceptions do not commit partial normalization. Recognizable secrets are redacted before normalized state or snapshots enter the cache.

Claude backfill prioritizes runtime-discovered sessions, rotates historical sources in batches of at most eight, and retains existing normalized projections for other files. Recent tails are bounded and reread only when source metadata changes. Codex uses bounded source batches and bounded concurrency. Polling reconciles names, roots, sources, and runtime evidence; correctness does not depend on filesystem notifications.

Lifecycle tests use isolated temporary roots. They cover split JSON/UTF-8 writes, CRLF/BOM, malformed records, duplicates, truncation, replacement, rename/archive, reducer rollback, restart, missing/locked files, concurrent replacement, bounded oversized-line skipping, and secret redaction. Provider integration tests run real adapters through the SQLite cache with synthetic histories and verified read-only CLI responses. They never mutate real agent histories or configurations.
